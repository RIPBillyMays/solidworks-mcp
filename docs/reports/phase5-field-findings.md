## Surprises

- `sketch_fillet` with `sketch_segments` pairs worked cleanly for 4 corners, but the segment order changes after every fillet, so each corner needed a re-list. This confirms finding #11.
- For #1, the snapping happens inside a single sketch and depends on other geometry already present. Isolated geometry and clean closed chains are exact, but crowded sketches (star + staircase + other lines together) snap hard. Probe 1c also shows the star vertices snapping to the world origin and to each other, which suggests the same-sketch inference, not just the 0.6 mm line proximity.
- `list_edges` reports a `point_mm` that does not look like an edge midpoint (e.g. (150,20,10) for a 100 mm edge from x=0..100).
- `get_mass_properties` fails with "no mass properties" while a sketch is open and no solid is yet built (expected), but also right after drawing in a part with an existing solid (it was called with Sketch3 open before the cut and the body existed). It worked after the cut.
- An unexplained event: the document `ESP32-C3 SuperMini.SLDPRT` (`sandbox/ref_models`, dirty=true) was open at the start and during probe 2. After `close_document` of `probe_assy.sldasm` it was no longer in `list_open_documents` (remaining count 3, expected 4). I never targeted it. Either the user closed it, or `close_document` closed it too. It was dirty, so unsaved changes may be gone. Ask Zach.
- The ESP32 document was under `sandbox/` so the "stop if not under sandbox" rule did not trigger, but it was never touched by any probe call.
